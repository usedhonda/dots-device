# 通常会話から端末回答までの確認手順

開発者がツールを直接呼ぶテストと、自分のDotとの通常会話からの往復を分けて確認します。[指示テンプレート](dot-instructions.md)を保存し、端末プラグインの接続と `device.answer` 購読を済ませてください。

1. 通常のチャットで、Dotに短い選択式の質問を端末へ送ってもらいます。
2. Dotの `device_publish_question` 成功と、同じ質問の実機表示を確認します。
3. 実機で候補を1回押します。即ホームに戻り、回答の吹き出しが出ます。
4. 回答イベントを受けたDotが、対象質問だけを `device_read_answer` で読みます。
5. 同じ質問・選択肢の実回答を確認したDotが、通常チャットへ受領を知らせます。
6. `device_record_receipt` が一致する回答へ受領を記録します。
7. 次の通常会話で新しい情報を話し、その返信後の `device_publish_summary` と実機表示の更新を確認します。

記録には自分の質問ID、選択肢ID、リクエストID、受領IDと時刻を使い、共有するサンプルには実際の会話や個人のIDを入れないでください。

| 観測 | 分かること | まだ分からないこと |
| --- | --- | --- |
| Wi-Fi接続、device_statusがonline | 現在の通信経路に到達できる | 会話由来の要約や質問が送られたか |
| publish成功 | 端末がツール処理を受け付けた | 実際の画面表示 |
| 1回押してホームへ戻った | ローカルで選択した | Dotが回答を受領したか |
| webhookが2xx | イベントの配送先に受け付けられた | Dotが回答を処理したか |
| 一致するreceiptが保存された | 回答に対応する受領が戻った | 別の外部業務が実行されたか |

端末不在時のテストは別に行います。通常チャットが続き、接続エラーが投稿されず、復帰後に古い要約がまとめて流れないことを確認します。実機の電源操作や重大な外部操作を、テストのために勝手に実行しないでください。
